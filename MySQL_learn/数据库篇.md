# 数据库安装

## Linux系统(centos7)

1. 直接安装

   ```bash
   yum install mysql-community-server -y
   # 如果成功，则不需要安装MySQLyum源
   # 如果出现以下错误，则需要安装MySQL yum源：
   # 'Loading mirror speeds from cached hostfile 没有可用软件包 mysql-community-server
   ```

2. 安装MySQL yum源（如果第一步安装成功，则不需要此操作）

   - 打开mysql官网：https://dev.mysql.com/downloads/repo/yum/

   - 根据自己的系统版本选择安装包

   - ![选择mysql版本](.\数据库篇.assest\选择mysql版本.png)

   - 点击Donwload，进来之后，拷贝下载链接

   - ![mysqlyum下载链接](.\数据库篇.assest\mysqlyum下载链接.png)

   - 使用wget命令下载MySQL yum源

     ```bash
     wget https://dev.mysql.com/get/mysql80-community-release-el7-7.noarch.rpm
     
     # 如果出现如下报错，说明wget没有安装：'-bash: wget: 未找到命令'，安装一下即可
     yum install wget -y
     ```

   - 安装安装MySQL的yum源

     ```bash
     rpm -ivh mysql80-community-release-el7-7.noarch.rpm
     ```

   - 查看MySQL yum源的安装包

     ```bash
     yum repolist all | grep mysql
     # 可以看到，默认启用的安装源是mysql80-community版本，
     # 但我们想安装的是mysql57-community版本
     ```

     ![yum的安装包](.\数据库篇.assest\yum的安装包.png)

   - 修改MySQL yum源的默认安装包

     ```bash
     yum-config-manager --disable mysql80-community # 取消默认安装mysql80-community版本
     yum-config-manager --enable mysql57-community # 设置默认安装mysql57-community版本
     
     # 执行上面两条命令过程中，如果出现如下报错，说明系统缺少yum-utils工具：
     # "-bash: yum-config-manager: command not found"
     # yum-config-manager 命令是 yum-utils 包中的一部分，需要先安装 yum-utils。
     yum install yum-utils
     # 安装完成后，再尝试执行 yum-config-manager 命令即可。
     ```

   - 安装5.7版本

     修改完MySQL yum源之后，再次执行：`yum repolist all | grep mysql` ，会发现默认启用版本已经变成了5.7

     ![修改yum安装包](.\数据库篇.assest\修改yum安装包.png)

     执行安装命令即可：

     ```bash
     yum install mysql-community-server -y
     ```

3. 启动mysql服务端

   ```bash
   启动mysql服务
   systemctl start mysqld.service 	# 启动mysql服务
   systemctl status mysqld.service # 查看mysql状态
   ```
   
4. 重置密码

   ```bash
   # 新安装的mysql服务端会有一个临时密码，存放在/var/log/mysqld.log中
   # root@localhost: 后面就是密码，查看到密码之后，进行登录，然后修改密码
   grep password /var/log/mysqld.log
   
   mysql -u root -p
   # 输入前面查看到的临时密码
   
   # 修改临时密码（首次连接是用不了update语句的，只能用ALTER修改密码）
   ALTER USER USER() IDENTIFIED BY '123';
   # 如果出现如下提示：
   # 'ERROR 1819 (HY000): Your password does not satisfy the current policy requirements'
   # 则说明系统要求的密码强度较高，请尝试输入更复杂的密码，有的需要包含符号、大写字母、小写字母、数字，以及长度可能也有限制，就尽量输入复杂的密码。
   ```

5. 忘记密码

   ```bash
   # 在 MySQL 配置文件中禁用密码校验
   vim /etc/my.cnf
   
   # 如果找不到vim命令，安装一下即可：'sudo: vim：找不到命令'
   yum install vim -y
   
   # 将 skip-grant-tables 选项添加到 [mysqld] 部分中, 然后重启mysql服务
   systemctl restart mysqld.service
   
   mysql -uroot -p	#跳过验证启动的服务端，可以免密码登陆
   update mysql.user set authentication_string=password('123') where user='root'and host = 'localhost';	# 跳过验证修改密码,没有密码强度限制
   flush privileges; # 刷新权限
   
   # 配置文件修改回原样，重启mysql服务
   systemctl restart mysqld
   ```

6. 统一编码(和mac一样)

   ```bash
   # 查看编码
   # 需登录mysql
   \s 
   # 修改配置文件即可
   vim /etc/my.cnf
   
   # 给/etc/my.cnf 做如下配置：
   [mysqld]
   character-set-server=utf8
   collation-server=utf8_general_ci
   [client]
   default-character-set=utf8
   [mysql]
   default-character-set=utf8
   ```

7. 修改密码校验规则

   ```sql
   # 查看当前校验等级
   # MySQL8.0版本中，变量通常以validate_password.开头
   # 在较旧的版本（如MySQL5.7）中它们通常以validate_password_（下划线连接）开头
   SHOW VARIABLES LIKE 'validate_password%';
   
   # 修改检验等级
   # 0或LOW：只检查密码长度。
   # 1或MEDIUM（默认）：检查长度、数字、大小写、特殊字符。
   # 2或STRONG：检查长度、数字、大小写、特殊字符，并且还会检查字典文件（防止使用常见单词）。
   
   -- MySQL8.0
   SET GLOBAL validate_password.policy = 0;
   -- 旧版本(5.7)
   -- SET GLOBAL validate_password_policy = 0;
   
   # 修改最小长度限制
   -- MySQL8.0
   SET GLOBAL validate_password.length = 6;
   -- 旧版本 (5.7)
   -- SET GLOBAL validate_password_length = 6;
   ```

   上述命令在 MySQL 重启后会失效。如果希望永久生效，需要修改 MySQL 的配置文件（Linux 通常是 `/etc/my.cnf` 或 `/etc/mysql/mysql.conf.d/mysqld.cnf`；Windows 是 `my.ini`）。

   在 `[mysqld]` 标签下添加：

   ```mysql
   validate_password.policy=0
   validate_password.length=6
   ```

## DDL 数据库定义语句

DDL 数据库定义语言，用来定义和管理数据库或者数据表 create drop alter show

```mysql
# ------------------------------------------------- DDL 操作数据库 -------------------------------------------------------

-- 增
create {database|schema} [if not exists] 库名 
[default]{character set = utf8mb4 | collate = utf8mb4_0900_ai_ci};

-- 删
drop {database|schema} [if exists] 库名;

-- 改
alter {database|schema} 库名 {
[default] character set = utf8mb4|
[default] collate = utf8mb4_0900_ai_ci|
read only ={default |0|1}
};

-- 查
show {database|schema} [like 'pattern'|where expr];
show collation [like 'pattern'|where expr];
show create {database|schema} 库名;  -- 查看创建数据库的SQL语句
```

```mysql
# ------------------------------------------------- DDL 操作数据表 -------------------------------------------------------

-- 所有对表的操作，都可以使用绝对路径的方式，这样即便不切换数据库，也可以操作数据库对应的表
select database();  -- 查看当前所在数据库
use 库名;  -- 切换数据库

-- 增
 create table [if not exists] 表名(
     字段名1 字段类型[(宽度)] [约束条件],
     字段名2 字段类型[(宽度)] [约束条件],
     字段名3 字段类型[(宽度)] [约束条件],
     字段名4 字段类型[(宽度)] [约束条件1 约束条件2]
     # ,foreign key(字段名) references 表名(字段名)
    )[[default] character set = utf8][engine = innodb];

create table 新表名 [as] select ...;  -- 复制表（不会复制主键约束等）
create table 新表名 like 旧表名;  -- 复制表结构（会复制主键约束等）

-- 删
drop table [if exists] 表名;

-- 改
-- 改数据表
alter table 表名 engine=存储引擎;
alter table 表名 rename [to|as] 新表名;
-- 改字段
alter table 表名 add [column] 字段名 字段类型[(宽度)] [约束条件] [first|after 字段名];
alter table 表名 add 约束条件|索引;
alter table 表名 drop [column]字段名;
alter table 表名 modify [column] 字段名 字段类型[(宽度)] [约束条件][first|after 字段名];
alter table 表名 change [column] 旧字段名 新字段名 字段类型[(宽度)] [约束条件]
[first|after 字段名];

-- 查
show tables [{from|in} 库名] [like 'pattern'|where expr]
show engines;
show create table 表名;
{explain|describe|desc} movies;
```



## DML 数据库操作语句

DML 数据库操纵语言，用来操作数据 insert, update, delete

```mysql
-- 增
insert into 表名(字段1, 字段2, ...) value(数据1, 数据2, ...);  -- 部分字段添加一条数据

truncate [table] 表名;  -- 删除所有记录，并更新自增

-- 改
update table 表名 set 内容 where 条件;
```

## DQL 数据库查询语句

DQL 数据库查询语言，用来查询数据 select

```mysql
select
    [distinct] 字段名1 as 别名1, 字段名2 as 别名2, ...
from
	库名.表名1 as 别名1 [join 表名2 as 别名2 on 条件]
where
	筛选条件
group by
	字段名1, 字段名2, ...
having
	筛选条件
order by
	字段名1{asc|desc}, 字段2{asc|desc}, ...
limit 
	[row_start,] row_count;
	
-- 执行顺序：
-- from -> on -> join -> where -> group by -> 聚合 -> having -> select -> distinct -> -- order by -> limit
```

## DCL 数据库控制语句

DCL 数据库控制语言，权限控制 grant, revoke, commit, rollback

### 用户管理

```mysql
-- 创建用户
create user '用户名'@'主机名'  identified by '密码';

-- 删除用户
drop user '用户名'@'主机名';

-- 修改用户
alter user '用户名'@'主机名' identified with mysql_native_password by '新密码';
update mysql.user set host='主机名' where user='用户名';

-- 查询用户
select * from mysql.user;
```

### 权限控制

```mysql
-- 分配权限
grant 权限列表 on 库名.表名 to '用户名'@'主机名';

-- 撤销权限
revoke 权限列表 on 库名.表名 from ' 用户名'@'主机名';

-- 查询权限
show grants for '用户名'@'主机名';

-- 刷新权限
flush privileges;
```

### 事务

#### 事务概述

```mysql
-- 查看事务的提交方式
select @@autocommit;

-- 设置事务的提交方式
-- 设置事务手动提交，1为自动提交
set @@autocommit=0;

-- 开启事务
-- start transaction; 
begin;

-- 提交事务
commit;

-- 回滚事务
rollback;
```



####  事务的四大特性

- 原子性（**A**tomicity）：事务是不可分割的最小操作单元，这个操作单元要么全部成功，要么全部失败

- 一致性（**C**onsisteny）：事务完成的时候，必须使所有数据都保持一致状态

- 隔离性（**I**solation）：在并发的时候，A事务在操作的时候，它不会影响B事务的执行；B事务在操作的时候，也不会影响A事务

- 持久性（**D**urability）：事务不管是提交还是回滚，它对数据库里面数据的改变，都是永久的。

####  并发事务引发的问题

- 脏读：一个事务读取到了另外一个事务还没有提交的数据

- 不可重复读：一个事务先后读取同一条记录，但两次读取到数据不同

- 幻读：一个事务查询某一条记录的时候，没有对应的记录，但是在插入记录的时候，又发现这条记录已经存在了，就好像出现了幻觉一样

####  事务的隔离级别

| 隔离级别   | Read Uncommitted | Read Committed | Repeatable Read（默认） | Serializable |
| ---------- | :--------------: | :------------: | :---------------------: | :----------: |
| 脏读       |        ✔︎         |       ✗        |            ✗            |      ✗       |
| 不可重复读 |        ✔︎         |       ✔︎        |            ✗            |      ✗       |
| 幻读       |        ✔︎         |       ✔︎        |            ✔︎            |      ✗       |

```sql
-- 查看事务隔离级别
select @@transaction_isolation

-- 设置事务隔离级别
set {session|global} transaction isolation level <隔离级别>;
```

## 索引

### 索引分类

* 逻辑分类

  * 主键索引

    > 存在主键，主键索引就是聚集索引
    >
    > 不存在主键，第一个唯一字段，将会被作为聚集索引
    >
    > 没有主键和有唯一字段，Innodb会自动生成一个rowid，作为隐藏的聚集索引

  * 唯一索引

    > 索引列的值必须唯一，但允许有空值

  * 常规索引

  * 全文索引

* 存储形式分类

  * 聚集索引

    > 索引的叶子节点直接包含完整的行数据
    >
    > 一张表只能有一个聚集索引（通常是主键）

  * 二级索引

    > 叶子节点不存储实际的数据行，而是存储对应行的主键值
    >
    > 通过二级索引查询时，通常需要先找到主键值，再通过主键回表查询数据

### 索引语法

```sql
-- 创建索引
create [unique|fulltext] index 索引名称 on 表名(字段名,...);

-- 查询索引
show index from 表名;

-- 删除索引
drop index 索引名称 on 表名;

-- 创建全文索引
create [unique|fulltext] index 索引名称 on 表名(字段名,...) with parser ngram;

-- 使用全文索引
select * from 表名 where match(字段名) against('关键词');

-- 创建前缀索引
create index 索引名 on 表名(字段名(n));

```

### 索引失效

* 最左前缀法则

  > 最左列必须存在,并且不跳过索引中间的列,如果跳过了联合索引中的某一列,后面的字段索引将会失效
  >
  > 如果出现了范围查询,范围查询右侧的索引将会失效

* 在索引列上进行运算或使用函数

* 类型转换（隐式转换）

  > 当索引列是字符串类型，但在查询时没有加引号（传了数字），MySQL 会进行隐式类型转换

* 模糊查询中以通配符开头

* OR 连接的条件中包含非索引列

### SQL提示

```sql
-- 建议走某个索引
select * from 表名 use index(索引名) where 条件; 

-- 不要走某个索引
select * from 表名 ignore index(索引名) where 条件; 

—— 强制走某个索引
select * from 表名 force index(索引名) where 条件; 
```
